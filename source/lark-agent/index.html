System · Architecture
How · Key technical decisions

01How to use on-call history?

Fine-tune
  • Turn tickets into training data
  • Stale as soon as new tickets land
  • Limited data, prone to overfitting
  • Risks the model's general ability
Summarize + RAG ✓
  • Agent turns each resolved ticket into a Q&A summary in a knowledge base
  • New tickets usable quickly
Risk: can it handle very complicated permission on-call issues well?

Validate first: before building, I summarized 30 real on-call tickets — the summaries were high quality, so I went ahead.

02Fixing weak answers from on-call history

  • Symptom: summary quality was high, but RAG answers were still weak.
  • Root cause: retriever couldn't separate relevant from irrelevant summaries.
  • Fix:
    • Retrieve more candidates, so truly relevant ones aren't missed
    • Upgrade the rerank model to one that understands on-call ticket summaries and scores them correctly
  • Result: correct answers 5/32 → 17/32 (16% → 53%) on real on-call questions, hand-picked and self-graded

03Reliable delivery, responsive experience

  • Decouple receiving from processing
  • Stream the reply back — typewriter effect in the same message
